# 网站需求目录（Skill 需求基线）

## A. 页面结构

1. 单屏布局：输入、画布、代码、控制面板首屏可见，页面无纵向滚动
2. **画布优先**：1366×768 下非画布区域（标题/输入/页签/控制）≤26% 视口高，画布卡片 ≥62%、SVG ≥50%；1920×1080 下分别为 22% / 76% / 66%
3. 顶部标题：LeetCode 题号 + 中文标题，居中、单行、16px；顶部栏 44–52px
4. 标题链接：新标签页打开题目页面
5. 左上返回：新标签页打开 Hot 100
6. 右上操作：算法思路按钮 + GitHub 徽标 + Star，与标题同一行
7. 间距：只允许 4/8/12/16px 四级；页面外层无 20px 以上连续留白，功能栏之间用 1px 分隔线分组
8. 工作区比例：画布 ≥68% 宽，代码栏 320–400px；画布卡片高度 100% 自适应
9. 控制栏单行：按钮组 | 进度条 | 步数，高度 ≤56px
10. 标题、输入、页签、控制栏均不得换行撑高；超长内容省略或进弹窗

## B. 输入系统

1. 单行紧凑输入条
2. 自定义输入 + 样例按钮 + 随机合法数据
3. 非法输入即时提示，不触发演示更新
4. 合法输入自动触发分镜重置和重算

## C. 多解法系统

1. 每种解法独立步骤序列
2. 每种解法独立代码映射
3. 每种解法独立画布渲染参数与镜头划分
4. 切换解法时重置当前播放状态

## D. 代码面板

1. 支持 Java/Python/Go/JavaScript
2. 默认 Java，语言偏好持久化
3. 行号、语法高亮、当前行高亮
4. 变量值旁注（watch 区 + 行联动）
5. 避免双向滚动；必要时优先保证可读性

## E. 画布系统

1. 支持拖拽平移与缩放
2. 默认居中，避免元素堆叠
3. 节点/边/数组/哈希/栈队列可视化
4. 状态迁移必须有箭头和文字说明
5. 空节点必须显式绘制（null）
6. 数据流（赋值、比较、指针移动）必须可视化
7. 每步必须有 `operation` 操作徽标与一句 `narration` 解说
8. 状态使用固定语义色板（current/compare/visited/done/path/error），图例始终可见且跨步骤稳定
9. 同一元素跨步骤复用稳定 ID 与坐标；使用 data join + 过渡，禁止整屏重建
10. 每帧唯一焦点，旧焦点转 visited 留痕；最终结果转 done/path
11. 动画时长使用统一 motion token，且短于播放停留时间；跳步先中断过渡
12. 支持 `prefers-reduced-motion`：关闭过渡但保留全部状态与信息

## F. 控制系统

1. 上一步 [←]
2. 下一步 [→]
3. 播放/暂停 [Space]
4. 重置 [R]
5. 速度切换（自定义组件）
6. 可拖拽进度条（绿色已播、灰色未播）

## G. 社群与品牌

1. 右下角交流群悬浮球
2. hover 显示二维码，比例不变形
3. 二维码必须位于 `public/assets/qrcode-community.png`，构建后仍可访问
4. 提示文案：扫码发送 leetcode 加入

## H. 工程与发布

1. 端口使用 30000-65535（避免默认冲突）
2. CI 必须执行 lint/type-check/build/test:coverage/test:e2e
3. GitHub Actions 发布 Pages，工作流位于 `.github/workflows/deploy.yml`
4. 构建时通过 `VITE_APP_BASE` 自动适配仓库名
5. README 双语且默认英文：`README.md` 为英文（GitHub 默认展示），`README.zh-CN.md` 为简体中文；两份结构一致、顶部互相链接，且只保留题目标题、一句话说明、题目链接、Pages 演示链接
6. GitHub 仓库描述必须为英文，说明题目与演示定位
7. GitHub 仓库必须配置 Topics，至少 6 个，且包含 `leetcode`、`algorithm`、`visualization`、`typescript`、`react`、`d3`
